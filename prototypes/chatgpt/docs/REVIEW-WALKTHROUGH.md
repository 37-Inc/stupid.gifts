# Stupid Gifts — review execution and recording plan

This script is preparation, not a recording. All eight release-candidate host cases in `../submission/review-run-ledger.json` are **Not run**. Earlier desktop/protocol receipts may guide rehearsal but do not prove the intended submission candidate, mobile behavior or a working video URL.

## Before running

Use the actual candidate version in a fresh ChatGPT conversation with Stupid Gifts enabled. Record its source revision, MCP endpoint, server/widget versions and actual host/device. The current private development connection may be used to rehearse its exact supported build; do not upload a public draft solely to obtain a recording. Confirm that displayed content is authorized for the intended review audience.

No user sign-in is required by the current read-only public-catalog design. If production later adds authentication, prepare reviewer access privately in the portal, not in the package or video. Do not expose unrelated chats, account pages, tokens or payment information.

## Walkthrough

1. Show the enabled app and a fresh prompt: “I need an unusual gift for my dad who loves cats.” Pause to show a real final carousel and concise surrounding response.
2. Follow with “No mugs or cups, please. What else would fit?” Show that the displayed selection respects the exclusion and still fits the carried interest.
3. Change to “Actually, this is for my sister who loves barbecuing.” Show an appropriate new selection and recipient wording. If the cleared catalog cannot support this interest, record that honest boundary and expand the reviewed cohort before claiming broad coverage.
4. Start a desk-gift selection, then request different gifts. Compare actual IDs/canonical pages against the prior selection; record an honest no-additional-results explanation if necessary.
5. Run the absent-keyword case and show an empty-result explanation, not a fabricated carousel.
6. Demonstrate the three unsupported requests: buying/shipping, order tracking and strict current-price/delivery comparison. Show their boundaries without a purchase, account access or invented facts.
7. Open an actual card and verify that it reaches its corresponding Stupid Gifts page. Do not click a retailer purchase control or make a purchase.
8. Capture responsive behavior on desktop and an actual mobile ChatGPT host, including horizontal scrolling, photos and readable titles. Check dark mode, focus/keyboard and screen-reader output in separate acceptance notes if not legible in the main recording.

Run additional controlled outage, missing-ID, withdrawn-product, broken-image and cross-instance tests outside the public walkthrough as needed. Label injected failures as synthetic; never describe them as observed catalog outages. Do not weaken production CSP or other protections to make a demo pass.

## Evidence and video completion

For each case save: actual prompt/context, selected candidate version, observed tool calls and IDs, visible outcome, device/host, Passed/Failed/Blocked/Not run and evidence path. Enter only supported schema fields in `plugin.draft.json`; execution outcomes stay in the separate ledger. A failed expectation is a fix/retest item.

Computer control and screenshots do not themselves provide a video recorder. Local browser automation was disabled in Work settings at the last attempt. If an authorized recording tool becomes available, use it for the visible walkthrough; otherwise have the owner start/stop their recorder while the flow is demonstrated. Play back the saved recording, inspect readability and accidental secrets, then host it at the chosen reviewer-accessible destination and verify playback without private permissions. Only then add the actual `review.demo_recording_url` and mark that gap complete.

[Current OpenAI submission requirements](https://developers.openai.com/plugins/deploy/submission) call for five positive and three negative cases, a working walkthrough URL and release notes. Do not confuse a script, uploaded draft or local test pass with completed public review.
